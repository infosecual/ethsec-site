How Argus works

Argus is EthSec's engine: a continuous-scanning, model-agnostic platform that finds and helps fix vulnerabilities in critical Ethereum code. This page explains how it is built, for engineers seeing it for the first time.

It runs as three layers in one loop. el-bigote carries the methodology and knowledge. dobby runs open models on owned hardware for the high-volume reading. A dispatcher runs each unit of work in an isolated sandbox across many compute lanes at once.

Layer one

el-bigote

Orchestration, methodology, and knowledge: the find-to-file loop, a large library of analysis lenses, and about 131 tools that turn a target into ranked, validated findings.

Layer two

dobby

The local-model workhorse. Open models on owned hardware do the high-volume reading; frontier models take the hardest reasoning. Breadth at near-zero marginal cost.

Layer three

Dispatcher

The compute and isolation layer. It runs each unit of work in a hardened sandbox, across many compute lanes at once, and never holds a credential centrally.

Together they form one continuous loop: inventory the code that matters, generate candidate issues at scale, validate them hard, disclose the real ones through the owner's channel, verify the fix, and begin again. Use the tabs above to go deeper on each layer.

Layer one

el-bigote: orchestration, methodology, and knowledge

el-bigote is the security-review framework at the center of Argus. It holds the methodology, the knowledge base, and about 131 tools, and runs a single loop from a first lead to a filed report. A few mechanisms do most of the work.

Lead generation at scale. Many diverse analysis lenses run over a target. A knowledge-base router loads only the vulnerability-class knowledge relevant to a given piece of code, so each pass is focused on what that code can actually get wrong rather than a generic checklist.

A validation gauntlet. Every candidate is attacked before it is believed: ensemble refutation, where k independent reviewers try to kill it; reachability analysis; differential testing; and fuzzing. An impact class is promoted only when a deterministic oracle fires on the exploit and stays silent on a matched control, so a claim rests on a test, not an opinion.

Compounding memory. A refuted-memory store records every dead end and is consulted before every hunt, so the system never re-derives a mechanism it has already ruled out. Each pass over the ecosystem gets cheaper and deeper than the last.

Choosing the next move. Work is ranked by a coverage-times-expected-value model, so effort follows risk and unreviewed surface instead of habit, and coverage is tracked against the exact version of each target.

The rule

A model's verdict is only a lead, never a confirmation. A senior researcher verifies and files. Nothing ships on a model's say-so.

Layer two · the local tier

dobby: the local-model workhorse

dobby runs the high-volume reading on open models on owned hardware, so breadth costs almost nothing at the margin. It uses a hybrid design: a frontier model orchestrates, planning the work and verifying the high-severity claims against real source, while a local open model does the bulk reading and triage.

No authority, typed output. The local model never executes tools. It reads text and returns structured, schema-validated JSON: a typed envelope carrying the result with a confidence score and its provenance. The orchestrator reviews that compact JSON and spot-checks only the top claims against the source.

Precomputed context, cached. The local model reads precomputed, deterministic context first, the call graphs, reachability, and taint flows produced by el-bigote's analysis tools, instead of raw code sprawl. That context is rendered deterministically so the inference engine reuses its KV cache and the expensive prefill is paid once across many calls.

Measured, not assumed. A model-comparison harness scores every model against deterministic gold labels and real confirmed findings, because standalone vulnerability-detection skill is close to random. Models are routed on measured recall and cost, not a public leaderboard.

Specialized, in progress. The open models are being fine-tuned with lightweight LoRA adapters on EthSec's own Ethereum-security corpus: past engagements and confirmed findings, the refuted-memory of dead ends, the lens and knowledge-base library, and the ecosystem's real Go, Solidity, and Rust code. Progress is measured on a two-sided benchmark that scores both recall (real bugs caught) and the false-affirm rate (confident wrong calls), because skill on C and C++ test sets does not read across to Cosmos-SDK Go or DeFi Solidity. The compute budget shifts toward owned hardware as the open models prove out.

The rule

A local model is a lead generator, not an oracle. Its output is untrusted data that the orchestrator and the deterministic tooling verify; it never has the authority to act, and a senior researcher verifies and files.

Layer three

The compute and isolation layer

Read top to bottom as one unit of work. Compute lanes supply capacity; the control plane assigns a unit to a lane and a sandbox; each sandbox runs wf-run against one target with exactly one credential; findings are harvested through dedup and attribution.   1. Credential-blind spine

    Built · 31 tests

    the part everything else sits on

    • Lanes registry with a no-secrets guard: metadata only, refuses any token value or secret-named field; a credential never lives here.
    • Impact-first scheduler: the queue is ranked by impact_priority (highs and crits coverage of the Argus scope); a bounty is a flag, never the ranker.
    • Best-ROI lane pick: local rig, then donated credits, then hosted model access, then a team environment, then metered API; cyber-use and opt-in gates; one active unit per account.
    • Hardened launch builder: generates the docker run and wf-run commands; refuses forbidden mounts; never puts a key in the argv. The security contract is asserted on the argv, so it holds without Docker.
    • Usage gate, locks, contained harvester: per-lane window gate from in-band signals, per-account concurrency locks, and a harvester that copies out into the engagement tree and never files.

  2. Real execute + two-account liveness

    Next

    prove isolation before any scale

    • Nine-stage launch-and-reap lifecycle: plan, prep (clone at pin), net (internal network + egress sidecar), acquire (lock), run, identity receipt, work (wf-run with heartbeat and journal sync), harvest, reap. Always reaps; resumes via wf-run --resume.
    • Identity guard: confirm the mounted login is the expected account before any work, without printing the token; a mismatch aborts.
    • Two-account liveness test: two isolated logins run concurrently on a trivial public target and must pass every row: concurrency, identity isolation, no token leak, no refresh-token collision, per-account window, kill-and-resume, clean reap.
    • Minimal kill-switch (stop-compute, stop-spill) and a dead-man lease so a lost control plane pauses rather than runs.
    adds lib/{sandbox,execute,identity,provision}.mjs · agent/Dockerfile · test/fake-docker + execute.test.mjs · LIVENESS.md
    Gate: the liveness test passes green on two provisioned accounts.

  3. Temporal control plane

    Planned

    durable, resumable, many at once

    • AccountLedger (one long-lived workflow per account): the slot gate holding live window state, concurrency, and the spill rule, replacing the single-shot usage gate.
    • UnitWorkflow (one per unit): reserve a slot, provision a sandbox, run the lifecycle with heartbeats, harvest, release; crash-resume from the journal plus Temporal history.
    • SandboxProvider adapters behind one interface: local Docker now, cloud later.
    • Layered kill-switch and a monthly drill: distinct stop-compute, stop-filing, stop-spill, revoke-credentials scopes, with an out-of-band path that does not depend on the control plane.
    Adopt: self-hosted Temporal (MIT). Keep ev-planner and coverage as the ranker, coord for human asks.

  4. Coordination across researchers

    Planned

    no wasted work, no duplicate filings

    • Claim board: lease a (target, surface, lens) so the fleet does not cover one surface fifty times, with an ensemble class for deliberate confidence and time-boxed leases against hoarding.
    • Cross-node dedup gate: cluster candidates by root cause before anything is filed, lock each cluster to one researcher; duplicates are unpayable and noisy to maintainers.
    • Attribution ledger: signed, append-only events for lease, spend, candidate, verification, filing, outcome; the source of truth for credit.
    • Program policy registry: per-program rules as a hard gate (one accountable human, AI disclosure where required, the filer reproduces the PoC), with a scope-drift watcher.
    Extends el-bigote coord.py; filing stays decentralized, each researcher under their own identity.

  5. Capacity allocator and telemetry

    Planned

    keep the whole fleet busy on the best work

    • Lane model and window telemetry: per-sandbox in-band window signals, no token leaving the owner's box; Claude Code OpenTelemetry for value-extracted-per-window.
    • Impact ordering in ev-planner: wire the impact rank and a coverage term so the allocator spreads across the 80+ targets; cost is not a gate (donated credits and the partnership).
    • Donated-credit ledger: each grant a tracked lot, used first, reported back to the granting lab.
    • Dashboards: fleet window board, coverage-per-target, verified-TP per lane, wasted-capacity, anomaly and runaway detection.
    Goal here is effective yield and a credible usage report to the labs, not budget control.

  6. Trust hardening and scale-out

    Planned

    from a few accounts to the fleet

    • microVM per unit and a credential-free PoC VM: for handed-over or hostile-code units, so a prompt-injected target cannot reach the credential while proving a bug.
    • Anti-poisoning of shared memories: per-node signing, advisory kills, canary re-derivation, so one malicious node cannot hide a bug from the fleet.
    • Cloud SandboxProvider (E2B or Modal) and the v2 wf-run cross-account diff so one run can span accounts.
    • Node signing and workload identity (Sigstore, SPIFFE), and a minimal researcher console (node state, window, pause, their claims and verification queue).
    Enters only after the liveness test and an early yield read justify scaling.

Standing posture

EthSec is a non-profit lab working in partnership with major model providers, so the binding constraints are security and quality, not budget: protecting embargoed findings, deduplication, the false-positive bar, and bounded loss when the operator is offline. The goal is highs and criticals found and fixed across the whole Argus scope, filed where a bounty exists.

Gate to scale past the two-account pilot: the verified-TP rate per unit, the duplicate-collision rate across researchers, the false-positive rate reaching a human, the re-auth cadence per account, and the kill-drill time-to-silence. Steps 3 through 6 enter only as those numbers hold. Nothing scales on the plan alone.
