EthSec is an independent security lab that points flagship AI at the Ethereum ecosystem's most critical code, continuously. Argus is its engine. This brief lays out what that effort proposes to cover, and where it points first.

Mission: secure the whole Ethereum ecosystem 14 domains mapped · 411 targets October 2026

The mission

Secure the entire Ethereum ecosystem

Not one protocol and not one slice. The base layer in a serious way as the top priority, then every L2, the application layer users touch daily, and the parts the market under-reviews: wallets, signing, hardware custody, and the shared code everything inherits. Direction follows where Ethereum is most exposed and where an independent lab adds what no single program does, set by security judgment rather than by which target pays best.

Point

Scarce capability at what matters most

Flagship, exploit-capable AI, held responsibly, aimed at the highest-consequence code, the base layer included, and at the critical gaps no bounty funds.

Multiply

Every contribution into more review

Model-agnostic compute turns dollars, model credits, or an auditor's hard-won lens into far more coverage than any one contributor could fund alone.

Return

The results to the commons

Coordinated fixes through the owner's own disclosure channels, and a shared body of methods that lifts the whole ecosystem's security floor.

Where Argus points first

Phase 1: six categories, covered to completion

Phase 1 commits to whole categories, not a hand-picked set of flagship targets. Each category has one detection lens that sweeps every target in it, so committing to a category means its full roster gets reviewed, not just its largest name. The six are the four the charter names directly, the base layer and all L2s and wallets and hardware, plus the two systemic foundations every other category inherits trust from.

1. The base layer

All 21 targets · top priority

The most deeply engaged category already; the near-term lever is the surfaces a bounty-shaped market structurally skips, where category-complete coverage is still missing.

  • Engine API: the EL-to-CL trusted boundary, unpayable and under-reviewed, implemented 11 times.
  • PeerDAS: newest live consensus surface, reimplemented six ways, already yielding.
  • MEV-Boost and relays: off-protocol, no bounty, over 90% of blocks flow through four builders.
  • Glamsterdam pre-activation: ePBS and block-level access lists, a review window that closes at mainnet.
  • Cross-spec ambiguity: the one share-independent class; a shared misreading can split many clients at once.
  • Shared KZG and validator lifecycle: one dependency behind every client's blobs; the ~$107B staked state machine.

How it works

Security as one continuous loop

A defense factory runs review as a loop where every pass feeds the next, so coverage and knowledge compound instead of resetting at each engagement.

Inventory

Map the code that matters across the ecosystem, pinned to each version.

Discover

Routed lead generation at scale, across many diverse analysis lenses.

Validate

Ensemble refutation, reachability, differential testing, and fuzzing.

Disclose

Route each confirmed issue to its owner through coordinated disclosure.

Verify

Diff-review the fix to confirm it closed, then start the loop again.

Model-agnostic routing

The best model for each task from any provider, scored on measured recall and cost. Open models on owned hardware carry the high-volume read; frontier models do the scarce, hardest verification.

Continuous, not a snapshot

In-flight code is a moving target, so each change is reviewed as it lands. Coverage decays with every version, and drift triggers a re-scan without a human in the loop.

Nothing ships on a model's say-so

A model's verdict is a lead, never a confirmation. Every finding clears a validation gauntlet and a senior researcher verifies and files it.
